Agile Requirements for GiggleGit

User Stories:
1. As a vanilla Git power-user that has never seen GiggleGit before, I want to quickly understand how GiggleGit differs from Git so that I can determine if it's worth using.
2. As a team lead onboarding an experienced GiggleGit user, I want to have clear documentation or training resources so that I can effectively onboard new team members.
3. As a developer working in a team, I want to be able to resolve merge conflicts using memes in an intuitive way so that I can keep my workflow smooth and fun.

Task for the Third User Story:
- Implement meme-based merge conflict resolution

Tickets for the Third User Story:
1. Title: Design meme-based merge conflict UI
   - Create wireframes for the meme-based merge conflict resolution interface
   - Ensure that users can select, upload, or generate memes in response to conflicts
   - Get feedback from early testers and adjust accordingly

2. Title: Implement meme selection and application logic
   - Develop the front-end logic for selecting and applying memes to merge conflicts
   - Ensure that the applied meme is logged in the commit history
   - Allow users to override or remove a meme if needed

Why is this not a user story?
"As a user, I want to be able to authenticate on a new machine."
- This is a feature request, not a user story. A user story should describe why the user wants something. A better user story would be:
  "As a user, I want to authenticate on a new machine quickly and securely so that I can access my repositories without unnecessary friction."
